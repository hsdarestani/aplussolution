# Weekly Stundenzettel

Web admin dashboard: Stundenzettel → Kalenderwoche → Housekeeping · PDF / Front Office · PDF. Hidden in Capacitor builds. Backend requires admin/manager authorization and does not write or mutate attendance records.

GET `/api/reports/stundenzettel.pdf?week=2026-W46&group=housekeeping` (or `front_office`). ISO week Monday–Sunday in Europe/Berlin; frontend defaults to last completed Berlin week. No email is sent.

**Primary time source: completed employee TimeEntry `clock_in` and `clock_out` (IST); fallback: exact scheduled Dienstplan start/end (PLAN) when no completed IST is available for that worker/shift.** The **Stundenzettel PDF alone** rounds the recorded Start **down** to the previous 15-minute mark and Ende **up** to the next 15-minute mark, independently: e.g. 11:10 Start -> 11:00; 11:10 Ende -> 11:15; exact quarter-hour times remain unchanged. This maximizes the displayed interval, and no further nearest-quarter rounding is applied. Original TimeEntry timestamps are never modified. For clock entries with seconds, use the employee-visible HH:MM precision before the outward rounding; displayed rows and totals reconcile. Overnight shifts and DST use UTC elapsed time. No break deduction, including when the TimeEntry stores break minutes. The PDF shows the full IST start-to-end interval if present; otherwise the precise original PLAN interval. Scheduled PLAN fallback is not quarter-hour rounded.

The Dienstplan selects non-cancelled shifts, work groups and hotel/client, and supplies the relevant employee assignments. Every assigned employee gets a row. If a completed linked TimeEntry is missing (including when only an open/incomplete timer exists), the employee/date row contains the **exact scheduled PLAN start/end and gross duration**; these hours are included in the displayed page total. PLAN fallback rows are clearly marked **PLAN (nicht erfasst)** in the existing confirmation cell so they are not mistaken for proven employee attendance. Completed IST rows retain their existing editable confirmation text; the fallback never creates, approves, or modifies attendance records. Unfilled OpenShift slots are omitted. Completed TimeEntries for released workers are included, since actual submitted evidence must not be lost when an assignment changes. For conflicting duplicate records of the same shift/worker, use the most recently updated finished TimeEntry; unfinished timers never override completed records. Recorded pending and approved IST entries are both visible; 'bestätigt' in recorded rows is form wording and does not change backend approval state.

The background is the emailed A+ form (5 Oct 2026), with original widgets/example data stripped. The original landscape A4 print layout remains editable. Department, hotel, every cell, and numeric footer are all editable PDF AcroForm fields. Fourteen employee rows fit each page, with numeric-only footer sum of displayed decimal hours. Changing start/end inside Adobe Acrobat/Reader with PDF JavaScript enabled applies the same outward quarter-hour rounding before updating row hours and page sum; other PDF viewers may not run JavaScript, but allow editing fields manually. Separate client/locations never merge, even when hotel names match. No WIW live API requests or persistent data modifications.

Verification: backend tests cover permissions, invalid weeks, employee-reported vs planned hours, pending submissions, missing/incomplete-IST PLAN fallback, active and cancelled slot cards, duplicate TimeEntry handling, released employees, editable PDF and total, overnight and DST; frontend UI tests cover download and errors. Read-only production verifier independently compares report HH:MM intervals to stored TimeEntries or exact scheduled PLAN fallback, with source labels and PDF page totals verified per group.
