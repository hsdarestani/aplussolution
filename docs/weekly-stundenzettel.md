# Weekly Stundenzettel

Web admin dashboard: Stundenzettel → Kalenderwoche → Housekeeping · PDF / Front Office · PDF. Hidden in Capacitor builds. Backend requires admin/manager authorization and does not write or mutate attendance records.

GET `/api/reports/stundenzettel.pdf?week=2026-W46&group=housekeeping` (or `front_office`). ISO week Monday–Sunday in Europe/Berlin; frontend defaults to last completed Berlin week. No email is sent.

**Time source: actual employee-entered TimeEntry `clock_in` and `clock_out`, not planned Dienstplan start/end.** Entries that employees already submitted in rounded HH:MM form retain exactly their entered hours/minutes; there is no extra quarter-hour rounding. The visible HH:MM precision is used for hours calculations to avoid displayed-time discrepancies. Overnight shifts and DST use UTC elapsed time. No break deduction, including when the TimeEntry stores break minutes. The PDF shows the full submitted start-to-end interval.

The Dienstplan selects non-cancelled shifts, work groups and hotel/client, and supplies the relevant employee assignments. Every assigned employee gets a row. If a completed linked entry is missing, the employee/date row remains but Start/Ende/Stunden are **blank** rather than substituted from PLAN; such rows add zero to totals. Unfilled OpenShift slots are omitted. Completed TimeEntries for released workers are included, since actual submitted evidence must not be lost when an assignment changes. For conflicting duplicate records of the same shift/worker, use the most recently updated finished TimeEntry; unfinished timers never override completed records. Recorded pending and approved entries are both visible; 'bestätigt' is form wording and does not change backend approval state.

The background is the emailed A+ form (5 Oct 2026), with original widgets/example data stripped. The original landscape A4 print layout remains editable. Department, hotel, every cell, and numeric footer are all editable PDF AcroForm fields. Fourteen employee rows fit each page, with numeric-only footer sum of displayed decimal hours. Changing an entry in Adobe Acrobat/Reader with PDF JavaScript enabled updates row hours and page sum; other PDF viewers may not run JavaScript, but allow editing fields manually. Separate client/locations never merge, even when hotel names match. No WIW live API requests or persistent data modifications.

Verification: backend tests cover permissions, invalid weeks, employee-reported vs planned hours, pending submissions, unmatched/unfinished rows, active and cancelled slot cards, duplicate TimeEntry handling, released employees, editable PDF and total, overnight and DST; frontend UI tests cover download and errors. Read-only production verifier independently compares report HH:MM intervals to stored TimeEntries and PDF fields per group.
